# Private GitHub backup

The private repository at <https://github.com/Jellofied/JelloGym> is a backup of this
working tree and the place where branches are kept. The public repository at
<https://github.com/DuarteSantos8/openGym> stays the upstream source. It is remote
`upstream` here and is never pushed to from this backup.

## Remotes

```bash
git remote -v
# origin    https://github.com/Jellofied/JelloGym.git   (private backup)
# upstream  https://github.com/DuarteSantos8/openGym.git (public, read only)
```

## Branches

- `main` is the integrated, tested state: the JelloGym rename, both audits and all
  audit fixes.
- `chore/rename-to-jellogym` keeps the classified rename commit on its own.
- `fix/*` keeps one audit finding per branch, so a fix can be reviewed or reverted
  on its own.
- `feature/water-1a` and `archive/public-main` keep the earlier local branches that
  predate the rename.

Work in a branch and open a pull request into `main`. Keep commits small and write
the reason in the commit message. Branch protection requires the `tests-ok` check
before a pull request can merge. Force pushes and branch deletion are off on
`main`.

## Checks before a pull request

The same gates used for the audit fixes apply here:

```bash
cd frontend && npm test && npm run build
cd api && npm test
cd mcp && npm test
node scripts/ci/deps-audit.mjs frontend api mcp
node scripts/catalogue/build.mjs --check
git diff --check
```

Training logic stays in pure `frontend/src/lib` helpers with a test beside it.
Generated locale and catalogue files are regenerated by their scripts, never
hand-edited. Exercise media stay at 180 px in Git and are never sent to an AI
tool. `data/` is ignored and is not part of this backup. Back it up separately;
GitHub holds the code, not your workouts or body measurements.

## CI in the private repository

`test.yml`, `audit.yml` and `ios.yml` are kept because they check the code. The
public-only workflows are removed from this backup: the GitLab mirror, Docker
publish, GitHub Pages demo, CLA, CLA issue and release check. They target the
public repository, its releases or its signing setup and must not run from a
private copy.
